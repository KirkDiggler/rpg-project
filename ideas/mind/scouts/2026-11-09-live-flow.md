# Scout: live NPC decision flow and seams for `mind/behavior/selection` (#2351)

Read-only trace on main branches, 2026-11-09. Toolkit paths are relative to
`/home/kirk/game-dev/rpg-toolkit/rulebooks/dnd5e/` unless they start with `mind/`.
Encounter and session both pin `mind/behavior v0.22.0`, `mind/machine v0.2.0`
(`encounter/go.mod:8-9`, `session/go.mod:8-9`). #2351 reaches the live stack only
at a consumer bump of those pins.

## 1. NPC decision path, end to end

1. **The raise.** A player verb pays world time: `advanceWorld` / `deedMovesTheWorld` /
   `spendWorldAction` / `spendWorldPace` (`encounter/worldtime.go:71,213,262,303`) end in
   `e.wake()` (`worldtime.go:231,279,331`) → `wakePass(raised=true, world=true)`
   (`worldtime.go:502,521`). A fight round calls `wakePass(raised, false)` from
   `flip.go:326`. Re-entrant calls are no-ops (`e.worldThinking`).
2. **Beats before time.** `wakePass` appends the `tick` beat (`appendTickBeat`), lands
   `clock: world`, then `matchLanded()` (`encounter/wakebeats.go:279`) so listeners hear
   the verb's beats first.
3. **Who is due.** Loop: re-read high-water, `e.due.Pop(at)` where `due machine.Due[MemberID]`
   (`encounter/encounter.go:261`). Skip members off the world clock, down, or with
   budget ≤ 0 (`clock.Budget`). Re-arm via `armAt` → `m.behaviorDue(now)`
   (`encounter/machine.go:281`). Only due members are asked (the S3 "raise wakes only who
   is due").
4. **One opportunity.** `stepMachine(id, m, round)` (`machine.go:331`) →
   `runBehaviorOpportunity` builds `behaviorOpportunity{on: beatTime, event: tickEv{Round}}`
   and calls `runIntents(nil, id, m, 0, &budget, 0, intentBound(budget), ClockWorld)`
   (`machine.go:352-362`). Fight turns reach the same `runIntents` from
   `driveMonsterTurns` (`clocks.go:317`, `clocks.go:568`) with `ClockTurn`.
5. **Facts gathered, per intent.** Inside `runIntents` (`clocks.go:606`), each loop
   iteration `j < bound` calls `buildMonsterView(m, budget, round)` (`clocks.go:2206`)
   → `MonsterView{Self, Key: e.pickKey, Actions, Table: m.Table, Temper: m.Temper,
   Deeds, AllyDeeds, OwnDeeds, Sounds, Known, Holdings, Seen, Remembered, Lost, Budget,
   Threats, Dwelling…}` (`clocks.go:2447`). Routes and threat zones are computed only if a
   table reads them (`behaviorReadsRoutes`, `behaviorNamesThreat`, `behavior.go:332,347`).
   `factsFromView(view)` (`encounter/facts.go:244`) turns it into `behavior.Facts`
   (When/sounds/known/threat/affordability). For verdict answers the equivalent is
   `factsFor(id)` (`facts.go:114`).
6. **Temperament.** `m.Temper` was dealt ONCE at the door: `dealTemperFor`
   (`worldtime.go:713`) → `behavior.Deal(ctx, &DealInput{Temper, Die: e.roller})`
   (`worldtime.go:732`), appends `tempered` beat (`answer.go:451`). Callers: launch
   (`encounter.go:1191`), join (`encounter.go:2906`), reserve release (`reserve.go:377`).
   Pre-checked by `validateTemper` (`worldtime.go:~680`), a hand copy of behavior's deal rules.
7. **Choice.** `selectDecision(m, view, opportunity)` (`behavior.go:249`):
   - `e.driver.Act(view)` first (`encounter.go:303` `driver Driver`). The default
     `TableDriver.Act` (`tabledriver.go:92`) calls `behavior.Pick(Key: time, Table,
     Temper, Facts, Die: d.Roller)` (`tabledriver.go:102`). A member with canonical
     behavior instances gets `Delegated{}` (`behavior.go:63,73`).
   - Delegated → `m.behaviors.composer.Decide(DecideInput{On, Event, Env, Now, Facts,
     Temper, Die: e.roller, Trace})` (`behavior.go:267`). `Composer.Decide`
     (`mind/behavior/composer.go:265`) previews every instance's machine step, takes the
     FIRST requesting instance in priority order (`composer.go:275-284`), runs
     `Pick` on that instance's key rows (`composer.go:294`), commits machine steps.
     Machine steps become `state` beats via `behaviorStepped` → `appendStateBeat`
     (`behavior.go:290`, `machine.go:367`).
8. **Row → intent.** `IntentForAnswer` (`intent_for_answer.go:24`) →
   `TableDriver.intentFor` (`tabledriver.go:125`): `Hold`→`Pass`, `Attack`→`attackIntent`
   (first authored action in reach), `Toward/Dash`→walk, `Away`, `Search`, `Fact/Say`→`Pass`
   with the voice landed separately. Selectors resolve via `selectMember` (`tabledriver.go:~605`,
   e.g. `nearestOpposed` `:640`). Behavior work (sequence/deed progress) via
   `behaviorRuntime.workFor` (`behavior_work.go:94`).
9. **Recorded, in order** (`clocks.go:676-705`), under act `time:<seq>` or the reaction's act:
   `behavior_config` (once), `answered` pick beat `appendPickBeat` (`clocks.go:785`, audience
   `subjectBeat` of the member), `behavior_decision` trace (`behavior_trace.go:98`), then
   `answerTime` (`answer.go:259`: voice sound + fact learned by witnesses+hearers). Then the
   intent executes in its own act: `behavior_work selected` → `executeTurnIntent`
   (`clocks.go:1017`) → moved/struck/etc beats.
10. **Client.** Session folds `answered` into `FamilyTableAnswer` (`session/act_family.go:58`,
    decoder `:760-820`) → proto `TableAnswer` (`rpg-api-protos/.../v1alpha2/act.proto:707`,
    oneof slot `table_answer = 34` at `:104`). `behavior_config/decision/work` are
    `recordOnly` (`act_family.go:35-38`), never shown to players.
11. **Randomness.** Only through `dice.Roller` handed in: `e.roller` (`encounter.go:170`) for
    picks/deals; `SpeakInput.Roller` for verdict answers. Session wraps `m.dice` in
    `diceSeam` (`session/initiative.go:132`, `session.go:347`, `social.go:85`). rpg-api
    supplies `&dice.CryptoRoller{}` by default (`rpg-api/internal/orchestrators/session/orchestrator.go:186`),
    overridable by `Config.Dice`. Not seeded in production; replay reads faces back from the
    record (`encounter/replaytest/replay_roller.go:208` `RecordRoller.Roll(size)`). No `math/rand`
    in encounter except keepgen's seeded placement (`dungeonspec/keepgen/place.go:231`).

## 2. Spoken answer / dialogue path

**A player-chosen reply already exists.** The player picks an authored `Option` (a line)
by ID; the NPC's answer is rolled.

- Authoring: `encounter.Option{ID, Say, Check []CheckApproach, Requires Trigger, Success, Failure []Answer}`
  (`encounter/option.go:61`). `Checked()` decides price (`option.go:106`).
- Offer: `OptionsFor(actor, target)` / `PropOptionsFor` (`option.go:178,211`) → `offered`
  filters by `requirementHolds` (`option.go:225,241`: `TriggerFact`, `TriggerHolds`,
  `TriggerNot`). Session `linesOffered` (`session/social.go:331`) → `readSpeakMenu`
  (`session/offers.go:~985`, within `InteractionReach = 3`, witnesses only) →
  `buildSpeakOffers` (`offers.go:783`) splits into a free row (`SlotNone`, plain lines) and an
  action row (`SlotAction`, checked lines) → `Declaration.SpeakOptions []SpeakOptionRow`
  (`session/afford.go:403`), every row `Available: true` (`offers.go:~900 projectRows`).
- Wire: `Declaration.speak_options = 23` (`rpg-api-protos/dnd5e/api/session/v1alpha1/types.proto:1546`),
  `SpeakOption{member_id|prop_id, option_id, line, available, shortfall}` (`types.proto:1795`).
  `rpc Speak(SpeakRequest)` (`service.proto:2438`), `SpeakRequest{session, member, target, option_id}`
  (`service.proto:1050`). Handler `rpg-api/internal/handlers/dnd5e/session/v1alpha1/speak.go:44`.
- Verb: session `Manager.Speak` (`session/speak.go:171`) → check staged/paused
  (`poseSocialWindow`, `social.go:386`) → `landSpoken` (`social.go:77`) → `encounter.Speak`
  (`option.go:436`): `spoke` beat, deed on a beaten check, then `e.answer` (`answer.go:187`)
  = `behavior.Pick(Key: success|failure, Table{key: rows}, Temper, Facts)` (`answer.go:198`),
  fact learned, `flee`, `answered` beat to witnesses, voice sound.
- Client: `SpeakAct` (`act.proto:532`) absorbs the `TableAnswer` (`act.proto:546`).
  Web: `ConversationPanel.tsx` lists `speakLinesFor(declaration, target)` and sends
  `onSpeakOption(optionId)` (`rpg-dnd5e-web/src/components/session/combat-experience/ConversationPanel.tsx:36,92-100`);
  `clickToAct.ts:96-111` offers Speak on a clicked creature; `useSessionSpeak.ts` calls the RPC.
  `npc-activities/sayActivityPresentation.ts:24` plays a `tableAnswer` activity cue.
- An NPC's own `time` line (`Say`/`Fact` row) is a voice with no player turn in it
  (`answerTime`, `answer.go:259`).

**What does not exist:** a multi-turn conversation (the NPC's answer cannot open a new menu of
replies), a menu evaluated with visible gate verdicts, and any "why not" for a withheld line.
Unmet lines are dropped on purpose (probe law, `session/social.go:322-329`, `offers.go:~892-897`).

**To make "player picks from an evaluated menu" use `selection`** (concrete shape to copy):
1. Encounter: an `OptionsFor`-like read that returns a `selection.Evaluation` over options
   (requirements = `requires` verdict, reach, witness, price) instead of the filtered list;
   `Speak` uses `selection.Choose(ID)` as its door so offer and door share one evaluation
   (today they share `requirementHolds` by convention, `option.go:644`).
2. A reply-chain primitive: an `Answer` row that names the next option set (e.g. `opens: <set>`).
   Nothing like it exists; inferred it belongs in `mind/behavior` answer vocabulary plus
   dungeonspec grammar and studio round-trip.
3. Session: keep `VerbSpeak`; extend `SpeakOptionRow` with per-line `Available/Why`
   (the struct and proto already carry `available` + `shortfall`, today always true/unspecified).
   A hidden-by-fact line must stay absent (R9), so only non-secret gates (price, reach) become
   visible Unmet evidence.
4. Protos: `SpeakOption.available/shortfall` already exist (`types.proto:1813-1818`). A conversation
   would need e.g. `SpeakOption.reply_to` or a `conversation_id` on `SpeakRequest`; analog is
   `TargetCandidate.approach = 6` (`types.proto:1299`), where the server names the choice it
   validated and the client must not substitute.
5. Web: `ConversationPanel` already renders a per-target line list; it needs disabled rows with
   shortfall text and to stay open after an answer.

## 4. What the record already carries

- `answered` beat (`answer.go:~385-416` `answeredBeatBody`): `key, verb, option, beaten, roll, of,
  entry, path, candidates[{entry, weight, percent, loaded}], rows` (full `RowVerdict` tree:
  `Held, Affordable, Weight, Percent, Loaded, Threat, Rows`, `mind/behavior/table.go:1519-1546`),
  `temper, word, selector, target, say, fact, activity`.
- `tempered` beat: `member, faction, temper, roll, of` (`answer.go:451-469`).
- `behavior_decision` (`behavior_trace.go:98`): `operation, on, now, outcomes[{id, definition,
  before, after, requested, selected, committed, skipped, step{fired, from, to, reason, acts,
  transitions[{index, on, evaluated, selected, guard}]}}], pick_record` (`:143-172`).
  No player audience (`encounter/doc.go:117-127`).
- **Reaches the client:** `TableAnswer` carries `candidates` (eligible rows only), `entry`, `roll`,
  `temperament`, `word`, `selector`, `say`, `dealt`, `activity` (`act.proto:707-735`). It does NOT carry
  `rows` (ineligible rows and why), `path`, or group dice; the session decoder drops them
  (`act_family.go:760-806`). The fact is withheld on purpose (R10). Behavior traces reach only the
  debug record surface. `selection`'s Unmet/Unknown evidence would be new data for the client;
  today only eligible weights are visible.

## 5. Risks for #2351 in the live stack

- **Size-ignoring test dice now fail.** Old `land` sent a face above the total to the last
  candidate; #2351 refuses it with `ErrBadTable`/`ErrBadMix` wrapping `selection.ErrBadRoll`.
  Test dice that ignore size: `session/launch_template_test.go:42` `faceDice` (castle kitchen
  launch at face 10, so any temper mix or table total < 10 now aborts launch), `session/testroller_test.go:78`
  `sequenceDice`, `session/attack_internal_test.go:76`, `session/exploration_review_test.go:17`,
  `session/selector_no_mutation_test.go:233`, `encounter/pursuit_internal_test.go:127` `facedDie`,
  `rpg-api/internal/orchestrators/session/orchestrator_test.go:70` `fixedRoller{20}`.
  Lowest-face dice (return 1) are safe. Inferred: failures surface only at the consumer bump,
  not in #2351's own CI.
- **Errors abort the player's verb.** Neither encounter nor session handles `ErrBadTable`/`ErrBadMix`
  (grep: no matches outside `mind/behavior`). `TableDriver.Act` maps only `ErrSilent`
  (`tabledriver.go:104-111`); a refused pick bubbles `act:` → `runIntents` → `wakePass` → the
  Step/Speak that raised the clock. A refused deal fails launch/join/reserve release
  (`encounter.go:1191,2906`, `reserve.go:377`). Production dice (`CryptoRoller`, `RecordRoller`)
  honor size, so live play is affected only by a bad die, inferred.
- **New Deal refusals vs `validateTemper`.** `validateTemper` (`worldtime.go:~680`) pre-checks share<1,
  unknown profile and no roller, but not share overflow. An overflowing mix now passes validation and
  fails at the deal. The hand copy drifts further; exporting a validator is the stated follow-up.
- **Per-decision cost multiplies.** Measured +~1.2 KiB and +16 allocs per `BenchmarkComposerDecide`
  (`docs/ideas/behavior-selection/implementation.md:20-28`). Each `judge` level now calls
  `selection.Evaluate` + `Inspect`, and nested groups are judged eagerly, so cost grows with rows and
  group depth. Picks per raise ≈ due members × intents per member (`intentBound(budget)`), plus one per
  verdict answer. At 10k with many due, inferred tens of thousands of extra allocations per raise.
  This is not measured in the keep harness yet; the live budget is ~165 ms per plain Move.
- **Recorded arithmetic must stay byte-identical.** Replay (`replaytest`) and the `answered` beat
  depend on `roll/of/path/candidates` matching old values. The PR claims valid outputs are unchanged;
  verify against a recorded keep log at the bump. Ineligible rows now append a `selection.Candidate`
  with `Percent` 0 (`table.go` judge diff), so check `RowVerdict.Weight/Percent` on unmet rows did not
  change from zero.
- **"One primitive" vs dialogue's probe law.** `selection.Inspect` exposes every Unmet row. Using it
  for player menus must keep fact-gated lines absent (R9, `session/social.go:322-329`); only
  non-secret requirements may surface as evidence.
