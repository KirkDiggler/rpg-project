What builds on what

The authored-behavior foundation (#866) is shipped: definitions, bindings, independent progress, precedence and real execution. This inspection wave (#898) explains that machinery. It does not add another NPC decision system.

Why JSON — and what is not changing

The payload is already JSON in the toolkit record. We are removing a lossy conversion, not moving game rules into JSON or replacing protobuf/Connect RPCs.

Approximate live projection

Toolkit JSON → protobuf Struct → browser numbers.

Struct uses doubles: 9007199254740993 can become 9007199254740992.

Exact diagnostic contract

Original JSON bytes → protobuf fields_json → lossless reader.

Record ID, act ID, beat and game-clock reading stay in the typed envelope. API capture carries the same payload without reconstructing it.

The reader must preserve integers too; ordinary JavaScript number decoding can lose them again. Missing/malformed data is unavailable evidence, never a guessed value. Probe and wire decision.

What the trace keeps separate

  • Configuration is not private runtime progress.
  • A false guard is not an unknown fact; an unvisited branch is not rejected.
  • A losing role's proposal is not committed progress.
  • A selected move is not arrival or completion.
  • A captured window is not automatically a complete run or simulation replay.

Costs and the optimization work

The UI keeps 500 visible rows but retains symbols independently. Session server history is currently unbounded. Export I/O is asynchronous and bounded; generating/copying/storing diagnostics still costs resources.

The bounded N10 garrison comparison adds about 103 KB/121 diagnostic records per four-cell op (default) or 45 KB/58 (posts asleep), including first-use symbols amortized over the run. These are not production latency guarantees: measurements and qualifications.

Your resident-instance work attacks repeated hydration and coordination costs. It is separate from record volume; this wave does not build a competing cache.
