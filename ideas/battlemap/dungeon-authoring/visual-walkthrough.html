1 · What an author writes now

One YAML file lives under rpg-api’s internal/content/dungeons/. The shipped reference-tomb is a three-room, fully static M1 example: entrance, hall, then a locked boss tomb. Gold values are pinned by the author; there is no private asset or game screenshot in this companion.

Strict means the file either loads or names the problem. Unknown YAML fields fail under strict decode; placements are validated before play. A place item routes by ref type: props becomes an obstacle and monsters becomes a positioned spawn. Light pools remain emergent from light-emitting props such as braziers — there is no lighting field.

2 · The placement contract

Room-local coordinates

at: [col, row] is local to its room: 0 ≤ col < width and 0 ≤ row < height. The compiler does not reproduce the region offset; the engine applies it when it realizes the dungeon’s shared absolute hex space.

One clear lane

For height: 8, row height / 2 = 4 is unavailable to place. This is the engine’s reserved door-row lane in every room, matching rolled-obstacle exclusions and preserving traversability by construction.

Static and rolled may coexist

Placed props and monsters claim their cells first; count-based obstacle rolls use remaining safe cells. A static placement (including boss.at) cannot be combined with pattern: scattered, because seed-rolled interior walls cannot promise its cell is clear.

4 · What runs where

The boundary stays intact: rpg-api hosts bytes and selects a key; the toolkit owns decoding, validation, compilation, placement, and monster semantics. No proto or web key-selection surface was added for M1.

The M1 walkthrough is a normal client route, not a test-only backdoor. Set RPG_CONTENT_DIR=… RPG_DUNGEON_KEY=reference-tomb, restart the API, then start an encounter from the host/lobby flow. The override is a development selection mechanism: when absent, M1 retains the legacy crypt default.

5 · Two ways to inspect the same file

Workbench

dungeonspec-workbench loads a file and seed, realizes the floor plan, runs SeedMonsters, and reports VALID plus an ASCII layout and exact placed entries. Its verdict covers the full M1 path, not decode alone.

Live edit/restart walkthrough

Use an RPG_CONTENT_DIR copy to edit YAML without rebuilding. Restart is required because the content registry is built at API construction. The selected reference-tomb can then be walked through the real game flow.
