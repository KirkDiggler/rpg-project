# Survey: #316 against current main (2026-08-30)

Verified against `rpg-toolkit` **origin/main @ e71918c** ("rename character id
in conditions to member id (#1319)") and `rpg-api` **origin/dev @ 40f0b3f**.
This is the re-verification Kirk's 2026-08-29 PR comment asked for. Every
inventory records the command that produced it (Phase 6 retro rule).

---

## Headline

The slice is smaller than #316 says and shaped differently than this design
assumed. **Three of the design's four "break points" are already fixed** —
Phase 5/6 and toolkit#1281/#1282/#1284 landed the OA grant (characters AND
monsters carry it at load), the readiness install (`installTruth`), the
trigger subscriber, and `resolution.NewMovement` itself with an 8-test suite.
What remains is genuinely one thing: **`NewMovement` has zero production
callers.** But the caller is not where the design says. Kirk's Done-when
scenario — a wolf standing next to his fighter turns to run — does not go
through `Manager.Move`/`runWalk` at all; a monster in a fight walks through
`encounter.executeTurnIntent`'s `Move` case, which loops `e.stepTo` inside
the bus-free, ctx-free encounter module. That path can no more call
resolution than it can swing a sword — which is exactly why `Striker`
exists. So the slice's central act is **a second capability seam beside
Striker** (a `Mover`), supplied by session, plus the symmetric wiring in
`runWalk` for the player's own walk.

Two further things must land or the Done-when cannot pass:

- `Character.CanReact()` returns **false on a cold sheet** — a fighter who
  has not yet acted this fight cannot take an opportunity attack. This is
  the gap Kirk's "every combatant is lit when the bubble forms" ruling
  closes, and it is still unimplemented (`session/economy.go:161-163` still
  states the lazy rule).
- `RecordInput` has no field for the "Opportunity Attack" label, so the log
  would show an unexplained hit during a monster's turn.

One design instruction is now actively **forbidden**:
`TestNoBusLivesInThisModule` proves session imports neither `events` nor
`gamectx` in production or test files, so "session subscribes
`ReactionTriggerTopic` and drains per step" cannot be built — and does not
need to be, because `NewMovement.collectTriggers` already does it.

## Findings

### F1 — The walk path today: THREE of them, not one

```
git show origin/main:rulebooks/dnd5e/session/move.go
git show origin/main:rulebooks/dnd5e/encounter/step.go
git show origin/main:rulebooks/dnd5e/encounter/clocks.go   # executeTurnIntent
git grep -n "stepTo(" origin/main -- rulebooks/dnd5e/encounter
```

**Path A — a player's walk (session-driven).** rpg-api `move.go:23` →
`sdk.Manager.Move` (`session/move.go:162`): validates the whole path,
charges `5 × len(path)` feet via `combat.Pay` before any cell is entered
(`move.go:230-263`), batches standing once, calls `runWalk` (`move.go:277`).
`runWalk` (`move.go:396-447`) is a bare loop over `scope.enc.Step(...)` —
publishes nothing, holds no bus. `encounter` never imports `events`.
**No rule can observe movement today** — the only production publisher of
`MovementChain` is `resolution/movement.go:223`, and `NewMovement` has zero
production callers.

**Path B — a monster's turn in a fight.** `encounter/clocks.go`
`executeTurnIntent`, `Move` case (~`:621-670`): loops `e.stepTo(m, cell)`
per cell, decrements `budget.MovementFeet` after the fact. Its sibling
`Attack` case calls `e.striker.Strike(context.Background(), e, ...)` — the
capability precedent.

**Path C — free-roam pump.** `encounter.go:1354` `stepTo` for
`IntentMoveTo`. World clock; shares `stepMember`; out of scope for OA.

`play/interrupt` exists and is dormant (`session/doc.go:125,132` scopes its
first honest producer to Wave 5). The per-step return channel is
`MoveOutput.Steps` + Outcome/Formed early-stop, not a suspension channel.

### F2 — `resolution.NewMovement`: full contract (built, tested, uncalled)

`MovementInput` (`movement.go:40-60`): `Mover`, `MoverKind`, `From`/`To`
(dungeon-absolute), `Reactions ReactionAttacks` (required capability —
asked per reactor at trigger time; `false` is an answer, not a failure),
`Roller` (required). Five door refusals before the world loads; input
copied, not borrowed.

R7 shape verified: `Start` is pure preflight → `announce()` subscribes
`ReactionTriggerTopic` for the duration of the fold (deferred unsubscribe,
`:254-268`), folds `MovementChainEvent` via `PublishWithChain` + `Execute`,
sorts buffered triggers by ReactorID then ConditionRef (C8), then `react(i)`
yields **one `Request` per trigger**, each wrapping `NewStrike` — one step
per trigger "is what the reaction WINDOW will need when a player is asked
rather than told" (`:272-276`). The reaction resolves **inside** this
interaction (`:136-140`: OA's meter marked itself used mid-fold; a separate
interaction would reload the sheet and find the meter empty).

**Announce-before-step is a contract** (`:142-154`): the reactor's strike
enforces reach against where the target IS; a caller that walks first hands
the strike a departed target, the strike refuses as out of range, and a
refused reaction fails the whole interaction. The caller announces the
step, then takes it.

Returns `MovementOutcome`: endpoints read off the folded event (never
echoed), `OAPrevented`, `Reactions []ReactionOutcome{ReactorID,
ConditionRef, Against, Struck}`. Installs nothing itself — driven by
`Resolve` → `installTruth` (`resolve.go:355`, `truth.go:58-107`), which
readies every participant for `freeReactions = [OpportunityAttack]`.

**Coverage gap:** the 8-test suite never uses the real
`OpportunityAttackCondition` — `triggerFrom` stands in for its publish
("this module cannot seat one," `movement_test.go:182-185`). Nothing
anywhere proves the real condition fires inside a real fold.

### F3 — The OA condition post-Phase-5/6

`conditions/opportunity_attack.go`: subscribes `MovementChain`
(`SubscribeWithChain`, `:152`) + `TurnStartTopic` (`:166`, rollback on
failure). Predicate order: not self → not `IsOAPrevented` → not
`UsedThisTurn` → `canReact(ctx)` → `gamectx.IsReactionReady` →
`RequireRoom` (missing room = silent no-op) → `isLeavingMyThreatRange`
(within reach at From, outside at To, reach = 1 cell).

`UsedThisTurn` is persisted, cleared on turn **start** (`:188-195` — a
meter cleared at end of its holder's turn would be full for the whole
window it governs). Writes are request-shaped (`:317-326`): flag, then
`publishSpendRequested(ActionReaction, 1)`, then `ConditionStateChangedEvent`.
Character keeper debits (`character/sheet_keeper.go:160`); the monster
keeper has no row for the topic — that IS the asymmetry. `canReact` fails
closed on not-in-cast (`conditions/member.go:52`).

**Both kinds now carry the grant:** `character/load.go:538-550`
(`freeReactionsToCarry`, at load, deliberately not dirtying) and
`monstertraits/loader.go:404-412` (at Attach, so Load stays a pure read).
Both cite Kirk's ruling verbatim.

**Two stale doc paragraphs** (`:54`, `:243`) still name the deleted
`Encounter.MoveEntity` as the drainer; the drainer is
`resolution/movement.go:254`. Fix rides whichever slice PR touches
`rulebooks/dnd5e` first.

### F6 — The seam: two precedents, and runWalk is the striker case

`Manager.Attack` (`attack.go:262-296`) adopts the returned world;
`strikerSeam.Strike` (`striker.go:114-137`) **never adopts** — enc is the
same live object the loop is mid-iteration over. `runWalk` is mid-loop over
`scope.enc`, so per step: snapshot `ToData()` (mover still at From) →
`Resolve(NewMovement{From,To})` → discard `out.World` → `saveDirty(out)` →
record reaction beats on the live enc → **then** `scope.enc.Step(cell)`.
Ordering forced by announce-before-step; it also keeps the reach check
honest.

`Cost` stays nil (the walk is already priced); `Participants` via the
existing `castFor` (loads every roster member — Kirk's law). Genuinely new:
a `ReactionAttacks` implementation answering "what does reactor X swing" for
both kinds (session already answers it for players via
`compileResolutionCast`/`attackRefFor` and monsters via `striker.go:70-81`).
Seam laws all hold: IDs+positions+capabilities cross, answers return,
session installs nothing.

For Path B: `executeTurnIntent` is inside encounter (no events import, no
ctx) — the only available shape is the Striker one: an `encounter.Mover`
capability, required at construction, called per cell from the `Move` case,
implemented in session as a `moverSeam` holding `*writeScope`
(`striker.go:20-27` pattern verbatim, `context.Background()` with the same
comment `clocks.go:~607` carries).

### F7 — Encounter side: nothing new needed

One canvas, one room; `Encounter.Canvas()` hands `readOnlyRoom` (mutators
refuse), which is what `installTruth` installs and what OA reads via
`RequireRoom`. From/To are dungeon-absolute, matching `MovementInput`'s
frame — no projection anywhere. Doors: a shut door already refuses by name;
multi-room steps are ordinary steps.

### F8 — Movement cost: SHELF, flagged

Player walk charged whole up front (`move.go:230-263`, no refund on
interruption — documented); monster turn charged per step after the fact
(`clocks.go:~648`). **The two paths already disagree about when movement is
charged** — named, not fixed here. Prone/difficult terrain have nowhere to
live under the flat model; `session/economy.go:72-87` names the adjacent
speed-modifier debt. All deferred per #316's "Not now" + Kirk's 2026-08-28
per-cell ruling.

### F10 — Cross-repo wiring

rpg-api is two hops (`move.go:23` → Manager) and needs almost nothing:

correlation; **the only missing thing is the label** — no

## Rulings Kirk may need

**R1 — The monster-turn seam: a second capability beside Striker.**
Wiring only `runWalk` ships a slice where a player walking away provokes an
OA but the wolf in the Done-when sentence does not. Recommend: yes — an
`encounter.Mover` capability, required at construction exactly as `Striker`
is, `moverSeam` in session on the strikerSeam pattern. Both paths reach one
`NewMovement`; "what a step provokes" stays a single answer.

**R2 — Light every combatant's economy when the bubble forms.** Already
ruled by Kirk on #316; naming it as BLOCKING work: `CanReact()` is false on
a cold sheet, so the fighter who hasn't acted yet cannot OA. Fight
formation must load, seed, and save every member's sheet. Confirm the cost
(formation goes from loading nobody to loading everybody).

**R3 — Close design decision 1 on the record.** "Does the slot still get
spent?" was built and answered by #318 D4 + toolkit#1281: `UsedThisTurn`
AND `SpendRequested`, keeper-applied. Recommend: record as ruled-yes (it is
also what keeps OA and Protection mutually exclusive).

**R4 — Restate the Disengage Done-when bullet.** Monsters have no route to
the Disengaging condition (`monstertraits/loader.go` routes four traits +
the free OA; no combat abilities). Recommend: "a **player** who Disengages
walks away untouched" — that path exists end to end. Monster Disengage is a
separate, larger question.

**R5 — `ThreateningEntities` is a dead field: delete or fill?** Recommend
delete (always-delete-unused): nothing populates or reads it; OA computes
threat itself from the room; a field that looks populated but never is, is
the fail-silent shape.

**R6 — Does an OA that drops the walker stop the walk?** Design decision 2
says yes-when-dropped and claims no new mechanism needed — but a downed
walker is a STANDING change, `runWalk` reads only Outcome/Formed, and
`discoveryStanding` is batched once per walk on the stated grounds that "a
Move cannot down or revive anyone" — **an OA makes that comment false.**
Recommend: stop the walk when a reaction's StrikeOutcome downs the mover;
requires re-asking standing per step and revising the documented invariant.
Wants Kirk's eye, not a quiet implementation choice.

## Proposed PR split

One in-flight PR per module, proto-first, no replace directives.

- **P0 · rpg-api-protos** — `ReactionRef{ref, name}` on `Struck` (field 12)
  and `Missed` (field 7). Additive; buf breaking guards; no hand-written
  tests.
- **P1 · toolkit `encounter`** — `RecordInput` gains `Reaction
  *ReactionIdentity` (presence-checked like AttackIdentity, never validated
  for meaning). Plus, if R1 = yes: the `Mover` capability (interface,
  required-at-construction validation, `RefusingMover`, the `Move` case
  calling it per cell). The long pole: a breaking construction change for
  every NewEncounter/LoadEncounter site.
- **P2 · toolkit `resolution`** — possibly empty. Only if R5 says delete
  `ThreateningEntities` or a genuine gap forces one.
- **P3 · toolkit `session`** — the bulk: `runWalk` resolves each cell
  through `NewMovement` (never-adopt, announce-then-step); `moverSeam`;
  one `ReactionAttacks` implementation for both kinds; reaction beats with
  the new identity; economy-at-formation (R2); pin `character.EndTurn`'s
  zeroing; restore the Disengage E2E player-side (R4); fix the two stale OA
  doc paragraphs (rides the first `rulebooks/dnd5e` PR).
- **P4 · rpg-api** — project the label through `convert.go`. Nothing else.
- **P5 · rpg-dnd5e-web** — FILE wire-anchored issue (render the label),
  Todo/unassigned. Not on the critical path.

Also worth knowing before planning: `resolution/step.go:29-31` defers
