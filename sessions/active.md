**PIVOT 2026-08-12 — the session SDK ([toolkit#935](https://github.com/KirkDiggler/rpg-toolkit/issues/935), docs [PR #936](https://github.com/KirkDiggler/rpg-toolkit/pull/936), open for Kirk's review).** Scoping #916 turned into something larger once we asked who the customer is. Four findings redirected it: (1) `encounter.Move` is a single **hop**, not a walk — an OA is a property of the path, but the walker need not be the encounter; (2) **walls were already real** (`spatial.Boundary` carries separate BlocksMovement/BlocksLineOfSight, registered by the composition, projected by Atlas) so a doorway is just an *unblocked crossing* — which means **T3 "sight never crosses a connection" is not geometry**, it's a room-scoped shortcut anchoring made obsolete (retiring it = a perception wave computing field-level LOS over Atlas, the only thing that sees every room at once; spatial can't own it, its boundaries are registered *within* a room and a doorway spans two); (3) **`Member` is `{ID, Kind, Room}`** — no HP, sheet, conditions, or attack, so **#916's headline cannot be built in the composition**: the window opens, the player answers "I swing," and there's nothing to swing with; (4) the customer's loop (load encounter+monsters+players → load into the encounter → act → get data back → save) is missing step two entirely. **Shape (Kirk-ruled):** the encounter stays *the world* (geometry/placement/perception/story/endings, aggregate discipline intact); a `rulebooks/dnd5e/session` manager above it is *the table* (entity roster, bus, resolution, interrupt custody) — composer of composers, AWS-SDK style. Game server implements repository ports trading in `Data` types and **never holds a domain object**; stateless per call (we're turn-based). Suspension reaches the customer as one thing: a verb returns `Pending` instead of done, `Answer` resumes it. **Strategy:** wrap what exists, migrate rpg-api once, replace behind it — the falsifiable claim being *after the migration wave, no subsequent wave changes an rpg-api source file*, gated by `gorelease` from the first tag. **Discipline that makes it a boundary and not a rename:** the acceptance scenes were written *before anyone opened the old code*. Also settled: three mechanisms, not one — **chain** for modification during resolution (rage's bonus damage), **bus** for observation (was I hit / turn ended / the curse watching for a priest), **checkpoint** (enumerated, suspension returned as a value) as the only place a pause is born; journey 052's rule was never "no bus", it was *control flow never rides the bus*. The trap is **not** an interrupt — it does its thing; a checkpoint's four outcomes are do-nothing / halt / resolve / ask, and only the last suspends. **DESIGN APPROVED by Kirk 2026-08-12**; `plan.md` added — six waves, cut by the rule *anything that shapes a public type goes in wave 1, anything purely internal waits* (under the gorelease promise the wave with the most trivial code carries the most irreversible decisions). **W0** encounter log retention (parallel, different module → `encounter/v0.4.0`); **W1** shell + free-roam verbs + event stream → `session/v0.1.0`; **W2** the interrupt spine → `session/v0.2.0`; **W3** entities on the bus → `v0.3.0`; **W4** combat, where rpg-api migrates → `v0.4.0`; **W5** reactions, closing #916 → `v0.5.0`. **W2 needs no combat** — the headline scene (Alice walks, ogre comes into view at step 3, world freezes, different process answers, she resumes) is entirely reachable with the composition's existing sight refresh, so the interesting thing lands second not fifth. **The most valuable wave-1 test is a boundary test, not a behavior test**: it fails if any exported signature references a type from encounter/combat/clock/intel/record/interrupt — that's what makes "rpg-api only bumps a version" mechanical rather than aspirational, and the plan records that if it proves unwritable the strategy needs rethinking rather than a workaround. Grounded survey: **rpg-api imports ZERO of the composition today** (verified — no reference anywhere), so W1 costs it nothing it has; its **22 files / ~6,700 lines** of old-stack combat orchestration (hydrate_players, character_resolver, combatant, turn_state_project, dnd5e_combat_resolver_phased, reaction_resume) migrate at W4 and are treated as *evidence about what a game server needs, never a specification to port*. Also ruled in-session: NPCs are session-scoped in `SessionData` with no repo until a durable NPC exists (asymmetric reversibility — adding a Config port later is compatible, removing one isn't); delete-on-death rejected (loses the corpse; players loot bodies); log retention configurable with an **extremely small default** because that makes full-resync the common path and keeps it exercised. **Next:** start W0 and/or W1. **#916** still untouched — re-point as W5 or close, Kirk's call.
